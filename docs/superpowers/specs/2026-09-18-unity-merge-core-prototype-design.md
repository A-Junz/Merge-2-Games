# Unity 二合核心玩法原型设计

## 背景

原始目录 `2.x_源码_装扮梦想家园_2.4.13ts` 是 Cocos Creator 2.4.13 TypeScript 工程，不是 Unity 工程。它包含 7×9 棋盘、物品生成、拖拽、合成、能量、任务、存档等系统，也包含活动、商城、广告和多渠道 SDK 等非核心功能。Unity 无法直接打开 Cocos 的 `.fire` 场景、Prefab 或 TypeScript 组件，因此本任务是一次有限范围的 Unity 重建，不是格式转换。

## 目标

在保留原 Cocos 工程不变的前提下，新建一个 Unity 2022.3.62f3c1 工程 `UnityMergePrototype`。工程必须能在当前 macOS 电脑上由 Unity Editor 打开，并在主场景中点击 Play 后完成“生成物品 → 拖拽/交换 → 合成升级 → 提交订单 → 获得金币 → 自动存档”的闭环。

## 验收平台

- 操作系统：macOS 14.5，x86_64。
- Unity：2022.3.62f3c1，使用本机已安装的 Editor。
- 运行方式：Unity Editor Play Mode。
- 画面：1080×1920 竖屏参考分辨率，Canvas 随窗口等比缩放。
- 输入：必须支持编辑器中的鼠标；事件接口同时兼容触摸指针。

## 非目标

本阶段不迁移原美术、音效、广告、渠道 SDK、数据上报、活动、商城、家园装修、教学引导、仓库、锁定格、生成器冷却、安卓/iOS/小游戏打包，也不寻求与原游戏数值完全一致。

## 技术方案

使用 uGUI 构建界面，并把玩法状态与 Unity 视图分离。纯 C# 域模型负责棋盘、合成、能量、订单和存档数据；MonoBehaviour 只负责创建界面、接收输入与渲染当前状态。这使核心规则可在 EditMode 中独立测试，也便于后续替换美术或导入原工程数据。

## 工程边界

- 原工程：`2.x_源码_装扮梦想家园_2.4.13ts`，仅作参考，不修改。
- Unity 工程：在同级目录创建 `UnityMergePrototype`。
- 主场景：`Assets/Scenes/Main.unity`。
- 核心代码：`Assets/Scripts/Core`，不依赖 MonoBehaviour。
- 界面与输入：`Assets/Scripts/Presentation`。
- 持久化：`Assets/Scripts/Persistence`。
- 编辑器建置工具：`Assets/Editor`，用于可重复地生成主场景。
- 测试：`Assets/Tests/EditMode` 和 `Assets/Tests/PlayMode`。

## 核心组件

### GameState

持有棋盘、能量、金币、订单、随机状态和上次能量计算时间。它是存档的唯一权威状态，界面不单独保存玩法数据。

### BoardModel

棋盘固定为 7 列×9 行，共 63 格，本阶段全部开放。它支持：

- 向空格移动物品。
- 交换两个不同物品。
- 将同物品链、同等级且未达最高级的两个物品合成为下一级。
- 拒绝最高级合成、无效格索引和不满足条件的合成。
- 查找空格、计数和移除指定物品。

### GeneratorModel

生成器作为棋盘上方的独立按钮显示，不属于 63 个棋盘格，不可拖拽、不可合成，也不占用普通物品存档槽。单击生成器时：

1. 确认剩余能量至少为 1。
2. 确认棋盘存在空格。
3. 扣除 1 点能量。
4. 在随机空格中生成两条链之一的一级物品，两条链概率各为 50%。

如果能量不足或棋盘已满，状态不变且返回可显示的失败原因。

### ItemCatalog

原型包含两条各 5 级的物品链。每个物品有稳定的 ID、链 ID、等级、显示名称和显示颜色。同链同等级物品才能合成；5 级是最高级。原型显示名称为“甜点 L1”至“甜点 L5”和“饮品 L1”至“饮品 L5”。

### EnergyModel

- 初始能量：30。
- 能量上限：30。
- 生成一个物品消耗：1。
- 恢复频率：每 30 秒 1 点。
- 启动时根据 UTC 时间戳计算离线恢复，不超过上限。
- 到达上限后重置累计时间，防止重复领取离线能量。

### OrderModel

同时存在 3 个订单。每个订单要求一种物品，数量为 1 或 2，物品等级为 1 至 4。奖励由等级和数量决定：`10 * 数量 * 2^(等级 - 1)` 金币。提交时：

1. 检查棋盘上精确 ID 的物品数量。
2. 数量不足时不修改状态，并返回错误。
3. 数量足够时移除所需物品，增加金币。
4. 为该卡位生成新订单，并避免与原订单完全相同。

### SaveService

存档使用 JSON，保存到 `Application.persistentDataPath` 下的 `merge-prototype-save.json`。存档包含版本号、所有棋盘格物品 ID、能量、金币、3 个订单、上次能量计算 UTC 时间和随机状态。以下操作成功后立即保存：

- 生成物品。
- 移动、交换或合成。
- 提交订单。
- 能量定时恢复。
- 执行“重新开始”。

存档不存在时创建新游戏。JSON 无法解析、版本不支持或格数不匹配时，记录警告并回退到新游戏，不让场景启动失败。

## 界面与交互

### 顶部状态区

显示标题、能量、金币、一行状态提示和“重新开始”按钮。状态提示用于显示合成成功、能量不足、棋盘已满、订单未满足和存档回退等信息。

### 棋盘区

使用 GridLayoutGroup 生成 63 个方格。生成器位于棋盘上方的独立按钮，视觉上与棋盘紧邻，避免它与 63 个可存档格子的索引混淆。每个物品格同时显示链名和等级，不仅靠颜色区分。

拖拽开始时提高当前格子的显示层级。松开时将源格和目标格交给 BoardModel 处理；模型返回移动、交换、合成或拒绝结果，然后整体刷新棋盘。拖到棋盘外时恢复原状。

### 订单区

底部显示 3 张订单卡。每张卡显示目标物品、当前数量/需要数量、金币奖励和提交按钮。满足时按钮可交互，不满足时仍可点击以获得明确提示，但不修改状态。

## 数据流

1. `GameBootstrap` 初始化 ItemCatalog 和 SaveService。
2. SaveService 读取存档；失败时创建默认 GameState。
3. GameState 计算离线能量，然后由 `GamePresenter` 渲染界面。
4. 输入组件把生成、拖拽或提交意图交给 GamePresenter。
5. GamePresenter 调用纯 C# 模型，根据结果更新提示、刷新视图并保存。
6. 视图从 GameState 重绘，不自行推测合成结果或订单进度。

## 初始状态

- 棋盘为空。
- 能量为 30/30。
- 金币为 0。
- 创建 3 个可由两条物品链 1–4 级物品满足的订单。
- 随机数生成器使用存档中的种子/状态，使测试可重现。

## 错误与边界处理

- 输入索引越界：拒绝操作，不改变棋盘。
- 拖到原格或棋盘外：恢复原状。
- 合成条件不符：交换不同物品；最高级同物品则拒绝并提示。
- 生成时无能量或无空格：不扣能量，不生成物品。
- 订单数量不足：不移除物品，不发奖。
- 存档写入失败：保留内存状态，在界面和 Console 显示错误，不中断当前 Play Session。
- 存档损坏：回退到新游戏并在 Console 记录原因。

## 测试方案

### EditMode

- 空格移动。
- 不同物品交换。
- 同链同级合成并清空源格。
- 不同链、不同级和最高级的处理。
- 生成成功时只扣 1 点能量。
- 能量不足和棋盘已满时生成失败且不改变状态。
- 订单满足时移除精确数量、发放正确金币并替换订单。
- 订单不满足时状态不变。
- JSON 存档往返后保留全部关键状态。
- 离线能量根据经过时间恢复且不超过 30。
- 损坏存档返回可用的默认状态。

### PlayMode

- Main 场景能启动，且无未处理异常。
- 界面生成 63 个棋盘格、3 个订单卡和 1 个生成器。
- 点击生成器后能量减少、棋盘出现物品且存档文件存在。

### 完整验证

1. Unity 批处理打开工程并完成资源导入，进程退出码为 0。
2. EditMode 全部测试通过。
3. PlayMode 全部测试通过。
4. 用 Unity Editor 打开 `Assets/Scenes/Main.unity`，手动完成生成、移动、交换、合成、订单提交和重载存档流程。
5. Console 无编译错误或未处理异常。

## 完成标准

- `UnityMergePrototype` 能由 Unity 2022.3.62f3c1 打开。
- Main 场景是 Build Settings 中的第一个场景，点击 Play 后立即进入原型。
- 用户可在没有原 Cocos 运行时或第三方包的情况下完成核心循环。
- 退出并重新进入 Play Mode 后，棋盘、能量、金币和订单恢复。
- 自动化测试与 Unity 批处理验证全部通过。
- 原 Cocos 工程不被修改。
