# 初始棋盘解锁与订单规则设计

**日期：** 2026-09-22  
**状态：** 已确认，待进入实现计划

## 目标

为 Unity 二合原型加入固定的 7×9 初始棋盘、三种棋盘解锁状态、按解锁状态限制拖拽与合成、初始默认订单序列、等级对应订单上限和合成链开放规则，以及发牌旁的重置游戏入口。

### 解锁状态

- `Locked`：不可拖拽、不可移动、不可交换、不可合成；图标被完整遮罩。
- `SemiUnlocked`：不可作为拖拽源；不能进行普通移动或交换；可以作为完全解锁格的合成目标；图标被右半遮罩。
- `Unlocked`：可以作为拖拽源或目标，支持移动、交换和合成；图标完整显示。
- 完全解锁格拖到半解锁格时，仅当两者同链同级且可以合成时允许操作；合成成功后目标格升级为完全解锁。
- 每次解锁变化后，所有未解锁格检查上下左右邻居；只要邻居存在半解锁或完全解锁格，就升级为半解锁。
- 初始棋盘中的物品本身不计入普通元素“已出现”记录，只有按现有游戏流程实际解锁/生成/合成后才计入。

### 订单数量与合成链开放

- 新游戏初始激活 1 个订单。
- 订单上限：1 级 1 个，2 级 2 个，3～5 级 3 个，6～10 级 4 个，11 级以上 5 个。
- 1～3 级开放 1 条；4 级开放 2 条，5 级开放 3 条；之后每提升 2 级额外开放 1 条，最多 10 条。
- 合成链开放数量公式为：`1～3级 = 1`；`4级及以上 = min(10, 2 + (level - 3) / 2)`，其中 `/` 为整数除法。

### 默认订单与刷新

- 新游戏固定订单序列为：订单 1 面团（102）、订单 2 小餐包（103）、订单 3 法棍（104）。
- 初始只激活订单 1；完成订单 1 后显示订单 2，完成订单 2 后显示订单 3。
- 完成订单 3 后恢复随机订单生成，并继续遵守等级可用链、订单上限和订单需求规则。
- 订单刷新仍遵守现有 5 秒间隔和最多 5 个订单限制。

### 重置游戏

- 发牌按钮右侧新增重置按钮。
- 点击后创建全新的初始状态：初始棋盘、解锁状态、金币、等级、经验、默认订单序列和刷新计时器全部恢复。
- 新状态覆盖当前存档，重置后重新从订单 1 开始。

## 实现结构

### Core

- `BoardModel` 保存每格物品 ID 和解锁状态，并在 `HandleDrop` 中执行源格/目标格权限判断、半解锁合成升级与邻接传播。
- `GameState.CreateNew` 使用集中式初始棋盘常量构建棋盘和解锁状态，避免 UI 或随机逻辑重复定义布局。
- `GameState.AvailableChainCountForLevel` 按新起点实现为：1～3级返回 1，4级及以上返回 `Math.Min(ItemCatalog.ChainCount, 2 + (level - 3) / 2)`。
- `OrderModel` 将 `InitialOrderCount` 改为 1，`MaxOrdersForLevel` 使用新等级区间，并维护固定订单队列直到订单 3 完成。
- `GameState.TrySubmitOrder` 继续负责经验、金币和刷新计时，但固定订单阶段优先取预置订单，不改变提交接口。

### Persistence

- 存档新增每格解锁状态字段，并提升存档版本。
- 旧版本存档继续读取：保留原棋盘物品，按中心格完全解锁、四邻接半解锁、其余未解锁初始化缺失状态。
- 新游戏和重置使用同一个初始状态构建入口，保证两者一致。

### Presentation

- `BoardCellView` 增加解锁状态显示：完整图标、半幅遮罩、全幅遮罩，并根据状态启用/禁用拖拽输入。
- `GamePresenter.RefreshBoard` 同步模型解锁状态；`NotifyCellBeginDrag` 和落点处理继续由 Core 进行最终校验。
- `GameUiView` 增加 `RestartButton` 引用；`UiPrefabBuilder` 和 `GameUi.prefab` 在发牌按钮右侧放置重置按钮。
- `NotifyRestart` 绑定重置按钮，创建新状态并保存。

## 错误处理

- 所有非法拖拽、锁定格操作和不允许的半解锁交换返回 `Rejected`，不改变棋盘。
- 存档缺少解锁字段时执行兼容初始化，不因字段缺失导致启动失败。
- 初始布局中的物品 ID 必须经过 `ItemCatalog` 校验；发现非法 ID 时测试失败，不静默替换。

## 测试范围

- 初始棋盘 63 个坐标逐格 ID 校验。
- 初始中心格、四邻接半解锁格和其余未解锁格校验。
- 完全解锁格的移动、交换和合成。
- 半解锁格不可作为源、不可普通移动/交换，但可以被完全解锁格合成。
- 未解锁格的所有交互均被拒绝。
- 半解锁升级为完全解锁，以及未解锁邻接传播。
- 初始订单数量、固定订单 1～3 顺序、第三单后的随机生成。
- 各等级订单上限和合成链开放数量。
- 重置状态和存档覆盖行为。
- 新旧存档解锁字段兼容。

## 明确假设

- 半解锁遮罩固定覆盖棋盘格右半部分；未解锁遮罩覆盖整个图标区域。
- 初始棋盘中的物品可以被看到对应的遮罩形态，但不会因为“预先存在”而计入已出现元素。
- 默认订单固定序列只影响新游戏和重置后的前三个订单，旧存档继续保留其已有订单。
