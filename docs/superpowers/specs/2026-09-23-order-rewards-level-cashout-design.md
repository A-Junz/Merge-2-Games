# 订单奖励、等级进度与模拟提现设计

## 目标

在现有 Cocos Creator 2.4.13 核心合成游戏中，移除普通生成器的等待冷却，将气泡冷却加速改为激励视频；在主界面顶部展示本地模拟现金余额、提现入口和订单驱动等级进度。每个订单交付奖励 Rp20.00 与 1 EXP，每次升级奖励 Rp30.00；达到 Lv10 后开放本地模拟提现。

## 已确认范围

- 只实现本地模拟提现，不调用真实支付、银行、钱包或服务端接口。
- 复用当前 `LevelMgr` 的等级作为唯一玩家等级，避免另起一个并行等级体系；继续提供既有等级读取接口，供顾客容量等功能读取。
- 订单按顾客交付完成结算：每个订单只结算一次，增加 Rp20.00 与 1 EXP。
- 当前等级 EXP 达到对应门槛时升级；每次升级立即增加 Rp30.00。超过门槛的 EXP 保留，如单次增量跨越门槛，按实际升到的每一级发奖。
- 门槛表（当前等级 → 升级所需 EXP）：Lv1→3，Lv2→4，Lv3–6→5，Lv7–9→6，Lv10–12→7，Lv13–16→8，Lv17–20→9，Lv21+→10。
- 进入新规则时保留本机已有等级，不补发历史订单奖励；当前等级 EXP、累计新规则订单数、金额从各自新存档字段初始值开始累计。
- Lv10 起可提现。提现按钮提取全部余额、将本地余额归零，并显示成功的模拟结果；等级不足或余额为零时不提现并说明原因。
- 普通生成器不再等待时间冷却：`OUT_ITEM_WITH_OPEN_CD` 变为立即可产出；`OUT_RANDOM_AND_CD` 次数耗尽后立即恢复次数，不等待定时器。现有固定数量、耗尽销毁和产出关系仍按配置执行。
- 气泡冻结状态保留其冷却时间；通过激励视频减少/清除气泡冷却。只有广告 SDK 成功回调时才改变冻结状态，失败、取消或无广告时不改变状态。
- 核心玩法中所有可达的金币扣费入口改为激励视频。已扫描到 `GameBottomView.clearCDTimeBtnClick()` 是当前核心界面明确扣金币入口；实现计划仍须复查其他可达扣费路径。金币收入和正向奖励不是扣费，不改成广告。
- 顶栏参考用户图1：左侧显示 Rp 金额和提现按钮，右侧显示 LV 与当前 EXP/升级所需 EXP 进度条。提现门槛以 Lv10 表达。

## 工程现状与约束

- 工程使用 Cocos Creator 2.4.13，主界面预制体为 `assets/game/prefab/GameView.prefab`，其中已有 `TopInfo` 区域。
- `GameView.foodMoveFinish()` 是顾客订单完成交付后的结算路径；订单奖励必须在此流程确认完成时触发，并以订单 ID 防止重复发奖。
- `LevelMgr` 当前基于本机 `level` 值和 `ItemID.EXP` / `LevelItemModel` 计算等级；新规则需要统一等级来源并阻止非订单 EXP 继续提升该等级。
- `GameBottomView.clearCDTimeBtnClick()` 当前根据冷却减少价格扣除 `ItemID.GOLD`；广告使用既有 `CMgr.helper.showRewardAd`。
- 不修改随包静态配置表作为玩家进度存档；玩家余额、当前订单 EXP、累计新规订单数及重复结算防护写入本机存储。
- 先不增加新的外部服务和依赖。

## 设计方案

### 成长与奖励状态

扩展现有 `LevelMgr`，作为等级、订单 EXP、订单累计数和本地金额的统一接口。订单交付完成时由游戏层调用单一的订单结算方法；该方法基于唯一订单 ID 检查是否已发放，若未发放则在一次状态提交中记账：订单数加一、金额加 Rp20.00、EXP 加 1，然后循环检查升级门槛并为每次等级提升增加 Rp30.00。保存后的状态通过底层游戏事件通知 HUD 刷新。

新存档字段包含版本、当前等级、当前等级 EXP、累计新规则订单数、金额余额和已结算订单 ID 集合。旧等级值保留；新等级 EXP 与余额不从旧经验背包或历史订单反推。达到 Lv21 后每级门槛保持 10 EXP。

为保证“由订单升级”，将不再让遗留的 `ItemID.EXP` 检查路径改变当前等级。其他代码仍可读取当前等级，且所有既有等级查询必须在新规则下继续返回同一个等级值。对等级表未覆盖的新等级，玩家等级、HUD 和 Lv10 提现门槛仍正常；依赖 `LevelItemModel` 的顾客容量采用可解释的最高已配置容量回退值。

### 生成器和气泡

移除普通生成器 `OUT_ITEM_WITH_OPEN_CD` 和 `OUT_RANDOM_AND_CD` 的等待态/计时流程，同时继续遵守已有产出次数与耗尽规则。气泡冻结由 `splitChance` 相关状态区分，仍可自然等待；加速按钮不再读取价格或扣金币，而是请求激励视频。广告完成回调才执行已有的解冻、次数恢复、模型状态刷新和界面更新逻辑；非成功回调不产生状态或资源变化。

实现时逐个检查 `FoodItemView`、`GridFoodItemModel`、`GameView` 和 `GameBottomView` 的状态处理，确保 generator cooldown 与 bubble cooldown 不互相误判。对当前未由核心界面暴露的旧系统费用入口，按可达性审计；不得把旧系统被动产生的金币奖励反向处理为付费动作。

### 顶栏与提现

复用现有 `GameView`/`TopInfo` 主界面空间添加紧凑 HUD：金额显示为 `Rp` 两位小数；等级侧显示 `LV N` 及 `当前 EXP / 门槛` 进度。金额或等级状态变化事件更新文本/进度，无需重建棋盘。

提现操作为本地模拟：先校验 Lv10 与正余额，再将全部金额从本地余额中扣除并显示模拟成功；不执行网络请求。余额不足或门槛未达时显示明确说明。余额与订单结算状态使用同一持久化状态单元，避免 UI 只显示但未保存。

## 错误处理与幂等性

- 重复完成回调或重复订单 ID 不重复增加金额/EXP。
- 金额、EXP 和累计订单数必须保持非负有限值；损坏/未知版本状态不得静默覆盖玩家原始数据，应采用已存在的本地恢复备份/提示原则。
- 广告回调失败、用户关闭广告或 SDK 未提供成功结果时保持原气泡时间、状态和余额。
- 提现过程中只修改本机模拟余额；无余额或等级不足不得扣款。
- 重置数据操作应清除成长存档并恢复默认等级/余额，同时遵循现有“保留声音偏好”行为。

## 验收标准

1. 新玩家从 Lv1、0/3 EXP、Rp0.00 开始；保存后的既有等级保持不变，新规则不补发历史订单奖励。
2. 每个唯一订单交付只发 Rp20.00 和 1 EXP；等级阈值正确，升级奖励每级 Rp30.00，Lv21+ 每级需 10 EXP。
3. 普通生成器的两类冷却产出不再等待计时，但产出次数、固定/随机产出和耗尽行为仍有效。
4. 气泡冷却仅在激励视频成功后提前完成；失败/取消时状态不变，且过程不扣金币。
5. 核心界面的其他可达金币扣费位置完成审计并改为激励视频，或者明确证明不是付费入口。
6. 顶栏金额和等级/EXP 进度与本机保存状态一致；重启后仍一致。
7. Lv10 以下提现被拦截；Lv10 且余额大于零时模拟提取全部余额并归零；没有真实转账调用。
8. 重置数据清除新的成长存档，声音偏好仍保留。

## 验证边界

测试和手工验证计划在实现阶段制定。当前已知 Cocos Creator 2.4.13 在此 macOS 会话启动受到 LaunchServices 阻断；在启动环境恢复前，不能将构建或运行声明为通过。实现后至少执行静态检查；可用时再通过 Creator 2.4.13 打开项目验证 TypeScript 编译及运行流程。
