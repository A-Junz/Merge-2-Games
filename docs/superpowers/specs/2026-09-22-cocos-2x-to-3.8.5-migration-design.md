# Cocos Creator 2.4.13 到 3.8.5 迁移设计

## 目标

在不改写原始 Cocos Creator 2.4.13 工程的前提下，建立一个由 Cocos Creator 3.8.5 打开的独立迁移工程，并让原工程的主场景在 3.8.5 Web Preview 中启动。

## 已确认的工程事实

- 原工程：`2.x_源码_装扮梦想家园_2.4.13ts/`
- 原工程元数据：`engine: cocos-creator-js`、`version: 2.4.13`
- 规模：445 个 TypeScript 文件、2 个 `.fire` 场景、67 个 prefab
- 启动场景 UUID：`007a43b6-f8dc-45d5-a373-012937b2de87`
- 本机已存在：`/Applications/Cocos/Creator/3.8.5/CocosCreator.app`
- 原工程含自定义 `packages/`、平台 SDK、广告/登录适配和旧版构建脚本

## 迁移边界

第一阶段只承诺 3.8.5 编辑器可打开迁移工程、资源数据库完成、主场景可加载并在 Web Preview 显示游戏画面。微信小游戏、Android/iOS、广告、支付、登录和其他原生 SDK 的真实调用属于后续阶段；它们不能阻塞 Web Preview 启动。

## 方案

采用双目录方案：

1. 原工程作为只读基线，保留 `project.json`、`.fire`、prefab、脚本和资源原样。
2. 创建 `3.8.5-migrated/` 迁移工作区，不复制 `library/`、`temp/`、`local/` 等 2.x 编辑器缓存作为运行时资产。
3. 使用 Cocos Creator 3.8.5 的“导入 Cocos Creator 2.x 工程”流程转换场景、prefab、`.meta` 和资源序列化格式；不通过只改 `project.json` 冒充迁移。
4. 先完成导入和主场景基线，再根据编译/运行日志分批修复模块导入、装饰器、节点/组件 API、资源加载和事件输入 API。
5. 将平台 SDK 和自定义编辑器包隔离在平台适配层；浏览器环境使用无网络、可重复的 stub，避免原生调用阻塞主场景。
6. 每个修复批次后重新打开项目并运行 Web Preview，保留错误日志和回退点。

## 目录与数据流

```text
2.x_源码_装扮梦想家园_2.4.13ts/   原始 2.4.13 工程，只读
3.8.5-migrated/                    3.8.5 导入、修复与验证工作区
docs/superpowers/specs/             迁移设计与验收记录
docs/superpowers/plans/             可执行迁移计划
```

资源数据流为：原工程 `assets/` → 3.8.5 导入器 → 3.x `assets/` 与资源数据库。脚本数据流为：原始 TypeScript → 迁移工程脚本目录 → 3.8.5 编译与 Web Preview。原工程的 `library/`、`temp/`、`local/` 不复制为 3.x 运行时状态。

## 兼容性处理原则

- 2.x 的 `.fire`、prefab、`.meta` 和组件序列化由 3.8.5 导入器转换；不先对序列化文件做全局字符串替换。
- 2.x 的全局 `cc`、`cc._decorator`、`cc.Component`、`cc.Node.EventType`、资源加载和 UI 访问 API 不假设与 3.x 兼容；每次改动必须由实际编译或运行错误驱动。
- 平台 SDK、广告、登录、支付、分享和设备 API 只在平台适配层修改；Web Preview 使用 browser-safe stub。
- 所有迁移产物、脚本修改、配置变更和日志只允许发生在 `3.8.5-migrated/`。

## 验收标准

### 必须通过

1. 原始 `project.json` 的 `version` 仍为 `2.4.13`，原工程未被 3.8.5 导入器改写。
2. Cocos Creator 3.8.5 能打开迁移工程，资源数据库完成且无持续导入失败。
3. 迁移工程的主场景能在 Web Preview 显示加载画面和游戏主界面。
4. 主场景启动阶段没有阻塞性脚本编译错误、场景序列化错误或资源缺失错误。
5. 迁移过程可从独立目录删除并重新导入，不依赖修改原工程来恢复。

### 后续阶段

- 原生平台 SDK 的真实登录、广告、支付和分享调用
- Android、iOS、微信小游戏等平台构建
- 2.4.13 与 3.8.5 的逐功能回归和性能对照

## 风险与回退

- 2.x 到 3.x 是引擎架构变化，首次导入可能产生大量 API 和资源兼容错误；按错误类别分批处理，不一次性重写 445 个脚本。
- 若某批次导致资源数据库或场景不可打开，删除并重新生成 `3.8.5-migrated/`，不触碰原工程。
- 若 3.8.5 的 GUI 导入流程在当前桌面会话不可用，记录实际错误并停在导入阶段，不通过手改版本字段声称迁移完成。
