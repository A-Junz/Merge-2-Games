# Cocos Creator 2.4.13 到 3.8.5 迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改原始 Cocos Creator 2.4.13 工程的前提下，生成一个可由 Cocos Creator 3.8.5 打开并完成 Web Preview 主场景冒烟运行的独立迁移工程。

**Architecture:** 先建立只读源快照与独立 staging 目录，再调用 3.8.5 内置的 2.x 导入器生成目标工程。后续修复只发生在 `3.8.5-migrated`，按编辑器诊断将脚本、资源序列化和平台 SDK 兼容性分批处理；第一阶段只把 Web Preview 主场景作为验收边界。

**Tech Stack:** Cocos Creator 2.4.13/3.8.5、TypeScript、Cocos Creator 2.x importer、Web Preview、macOS shell。

**Spec:** `docs/superpowers/specs/2026-09-22-cocos-2x-to-3.8.5-migration-design.md`

## Global Constraints

- 原始工程 `/Users/edy/Documents/ChatGPT/二合/2.x_源码_装扮梦想家园_2.4.13ts` 只读，不在其中运行导入器或直接修复。
- 所有生成物放入 `/Users/edy/Documents/ChatGPT/二合/3.8.5-migrated`；不复制 `library/`、`temp/`、`local/`、`.DS_Store` 等缓存。
- 不用改版本号伪造迁移；必须使用 Cocos Creator 3.8.5 的“Import Cocos Creator 2.x project”。
- 第一阶段不承诺原生平台、广告、支付、登录和联网服务；这些调用要保留原生路径，并在 Web Preview 中隔离为安全 stub/guard。
- 每个批次都要先记录诊断，再修改，再重启编辑器并复测；不得用大范围盲改掩盖错误。

## Task 1: 建立源快照与迁移工作区

- [ ] 读取原工程的 `project.json`、`settings/project.json` 和 `assets/Scene/Main.fire`，确认版本为 2.4.13、启动场景 UUID 和设计分辨率。
- [ ] 创建 `3.8.5-migrated/source-input/`、`source-manifest.txt`、`migration-notes.md`，并将源工程中的 `assets/`、`packages/`、`config/`、`data/`、`move/`、`sarsgamexlsxparser/`、`creator.d.ts`、`jsconfig.json`、`tsconfig.json`、`project.json`、`settings/` 复制到 `source-input/`。
- [ ] 用 `rg --files` 及 `find` 记录 `.ts`、`.fire`、`.prefab` 和纹理数量；用 `shasum` 抽查 `project.json`、`Main.fire`，确保源文件和快照一致。
- [ ] 验证原工程 `project.json` 仍是 `"version": "2.4.13"`、`"engine": "cocos-creator-js"`，并记录源目录绝对路径。

**Gate:** 源工程没有写入变化，`source-input/` 可独立作为 2.x 导入输入，清单中包含启动场景 UUID。

## Task 2: 用 Cocos Creator 3.8.5 执行官方导入

- [ ] 启动 `/Applications/Cocos/Creator/3.8.5/CocosCreator.app`，通过 File → Import Cocos Creator 2.x project 选择 `3.8.5-migrated/source-input/`，输出目录选择 `3.8.5-migrated/`。
- [ ] 等待 Asset Database 完成导入；将 Console 中的导入警告、错误、失败资源路径记录到 `3.8.5-migrated/import-log.txt`，不在源工程中重试。
- [ ] 确认目标目录生成 3.x `project.json`、`assets/` 和必要的 `settings/`，且目标元数据不再声明 `cocos-creator-js` 或 2.4.13。
- [ ] 关闭并重新打开目标工程，验证导入结果可被 3.8.5 独立识别。

**Gate:** 3.8.5 能打开目标工程，Asset Database 不再持续重建，导入错误已按路径归档。

## Task 3: 建立导入基线并定位首个阻塞点

- [ ] 生成 `3.8.5-migrated/import-baseline.txt`，记录 `.scene`/`.fire`、`.prefab`、`.ts`、纹理等数量，并定位迁移后的 Main 场景。
- [ ] 在编辑器中打开迁移后的 Main 场景，先不改代码，记录无效序列化、丢失脚本、丢失 UUID 和资源导入错误。
- [ ] 先执行一次 Web Preview/Play，记录第一组阻塞性错误的完整文件、行号和调用链，写入 `migration-notes.md`。
- [ ] 将错误按“编辑器序列化、TypeScript 编译、运行时逻辑、平台 SDK、非阻塞警告”分类，后续每批只处理一个主类别。

**Gate:** 有一份可重复的错误基线；不以“能打开编辑器”代替“主场景可运行”。

## Task 4: 按诊断批次迁移脚本与组件 API

- [ ] 只修改 `3.8.5-migrated/assets/**/*.ts`（必要时同步 `creator.d.ts`），建立 `script-migration-log.md`，每条记录旧写法、新写法、影响模块和复测结果。
- [ ] 批次 A：处理模块导入与装饰器（`cc`、`cc._decorator`、`@ccclass`、`@property`、组件注册）及其直接编译错误。
- [ ] 批次 B：处理节点/组件/事件访问（节点查找、组件获取、生命周期、事件监听/解绑、Prefab 实例化）及其依赖链错误。
- [ ] 批次 C：处理资源与异步 API（资源加载、SpriteFrame/Texture、旧 loader、定时器、音频和持久化接口），仅按实际诊断修改。
- [ ] 每完成一个批次，完全退出并重启 3.8.5，重新打开 Main 场景、重新编译并 Preview；保留前后错误数量和首个错误变化。

**Gate:** Main 场景依赖图中不再出现阻塞性 TypeScript 编译错误；剩余问题必须能归类到平台或非阻塞范围。

## Task 5: 隔离平台 SDK 与自定义 package

- [ ] 清点 `3.8.5-migrated/packages/`、`build-game/` 和 `assets/Script/sdk` 的初始化入口，记录到 `platform-compat.md`。
- [ ] 对微信/QQ/快手/OPPO/VIVO/小米/4399 等原生专用调用增加运行环境判断；Web Preview 只提供最小安全 stub，避免模块初始化异常、窗口对象缺失或网络请求阻塞。
- [ ] 不删除原生分支、不伪造支付或广告成功；stub 只返回可继续启动所需的明确默认值，并记录潜在功能差异。
- [ ] 关闭并重新启动编辑器，验证自定义 package 不再导致导入/编译阶段异常。

**Gate:** Web 环境启动不被平台 SDK 阻塞，原生路径仍保留且差异有文档说明。

## Task 6: Web Preview 主场景验收

- [ ] 在 3.8.5 的 Project/Build Settings 中将迁移后的 Main 场景设为启动场景，确认场景 UUID 与 Task 1 记录一致或记录变更原因。
- [ ] 启动 Web Preview，生成 `3.8.5-migrated/preview-verification.md`，记录时间、端口、预览 URL、浏览器控制台错误和截图/现象。
- [ ] 验证页面加载、主场景渲染、首个交互 UI/弹窗出现；区分阻塞错误与已知平台 stub 警告。
- [ ] 关闭编辑器后从干净进程重新打开目标工程并再次 Preview，排除仅靠缓存成功的情况。

**Gate:** 3.8.5 可重新打开目标工程，Web Preview 可加载并渲染主场景，且没有阻塞性编译、序列化、资源缺失或运行时初始化错误。

## Task 7: 交付记录与回归核对

- [ ] 在 `migration-notes.md` 中汇总已完成迁移、已知限制、平台差异和后续可选工作；按编辑器/运行时/平台/非阻塞分类剩余诊断。
- [ ] 记录准确的重开方式：3.8.5 应打开的工程目录、Main 场景路径、Web Preview 操作和日志位置。
- [ ] 最后用 `shasum`/`diff` 核对原工程 `project.json`、`settings/project.json`、`assets/Scene/Main.fire` 与 `source-input/` 快照未被改变。
- [ ] 用 `rg` 检查目标工程没有指向原工程绝对路径、没有把缓存目录当作源资源，也没有残留仅为调试而加入的临时脚本。

**Final acceptance:** 原工程仍保持 2.4.13；`3.8.5-migrated` 可由 Cocos Creator 3.8.5 打开；Main 场景能在 Web Preview 中完成第一阶段冒烟运行；所有未完成平台能力有明确记录。

## Review Focus

- 导入是否始终使用 3.8.5 官方 2.x importer，而不是版本字段伪造。
- 任何脚本修复是否有具体诊断依据，是否避免一次性改写整个工程。
- Web Preview 的成功是否经过干净重启复测，是否把平台 stub 警告误报为“全部功能完成”。
- 源工程只读约束、缓存排除、原始文件 hash 核对是否在交付前完成。
